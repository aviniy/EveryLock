# 로컬 공격 시뮬레이션

실제 포털에서 관찰한 위험 패턴을 `127.0.0.1`에서만 재현한다. 모든 학생 정보, 학부모 관계, 세션 값과 오류 메시지는 가짜 데이터다.

현재 화면은 포털의 공개 로그인 HTML에서 확인한 `login_left`, `login_right`, `login_link` 배치와 공개 배경·로고·아이콘을 로컬에 반영했다. 공개된 jQuery 1.12.1 파일도 로컬에서만 불러온다. 실제 로그인 action, 인증서 모듈, 학사일정 API 및 외부 바로가기는 모두 제거하거나 가짜 로컬 동작으로 교체했다.

## 실행

Node.js 18 이상에서 다음 명령을 실행한다.

```powershell
node server.mjs
```

브라우저에서 `http://127.0.0.1:4173`을 연다.

## Python 계정 잠금 요청 시뮬레이터

`tools/everylock_attack_sim.py`는 `127.0.0.1:4173`의 로컬 `/api/login`만 호출한다. 코드에서 HTTP 방식, loopback 호스트, 포트 4173을 모두 검사하며 다른 주소와 리다이렉트를 거부한다.

먼저 요청 없이 생성 규칙을 확인한다.

```powershell
cd tools
python everylock_attack_sim.py --dry-run --users 100 --attempts 10 --seed 2026
```

로컬 랩 상태를 초기화하고 계정당 10회의 실패 이벤트를 초당 20개 속도로 실행한다.

```powershell
python everylock_attack_sim.py --users 100 --attempts 10 --rate 20 --seed 2026 --reset-lab
```

가상 학번은 `2023|2024|2025|2026` + 숫자 6자리이며, 비밀번호는 영문 대·소문자와 숫자로 구성된 8자리다. 생성된 비밀번호는 출력하거나 보고서에 저장하지 않는다. `--users`는 최대 1,000, `--attempts`는 최대 10, `--rate`는 최대 초당 100으로 제한된다.

시뮬레이터 자체 테스트:

```powershell
python -m unittest -v test_everylock_attack_sim.py
```

## Windows EXE 공격 콘솔

웹 UI가 아닌 네이티브 Windows 도구는 다음 위치에 빌드된다.

```text
release\EveryLock.exe
```

먼저 로컬 포털 서버를 실행한 다음 EXE를 연다.

```powershell
node server.mjs
.\release\EveryLock.exe
```

EXE 상단에서 대상 호스트와 포트를 바꿀 수 있다. 포털 개발 서버의 포트가 달라져도 바로 연결할 수 있지만, 격리 범위를 지키기 위해 호스트는 `127.0.0.1`, `localhost`, `::1`만 허용한다. `TEST CONNECTION`으로 현재 주소의 API 상태를 먼저 확인할 수 있다.

가상 학생 수, 계정당 실패 횟수, 초당 이벤트 수와 시드를 설정할 수 있으며 실행·일시정지·재개·초기화를 지원한다. `Chance Pattern`에 `202601----`, `Chance %`에 `90`을 입력하면 생성 계정의 정확히 90%가 해당 접두 패턴을 따르고 나머지 10%는 그 패턴 밖에서 생성된다. 모든 학번은 `2023|2024|2025|2026` + 숫자 6자리인 완전한 가상 값이다.

상단 `TESTLOCKER`는 입력한 단일 가상 학번 하나로 랩을 초기화하고 그 계정에만 10개의 실패 이벤트를 보내 잠금 흐름을 빠르게 확인한다. `UNLOCK ALL`, `EXPORT LOG`, `CLEAR` 버튼으로 잠금 해제, JSON 결과 저장, 콘솔 정리를 수행한다. 계정이 잠기면 네이티브 터미널에 `2026xxxxxx Lock Success!`를 표시하고 우측 목록에 학번, 실패 횟수와 잠금 시각을 추가한다.

EXE를 다시 빌드하려면 PyInstaller를 설치하고 빌드 스크립트를 실행한다.

```powershell
python -m pip install pyinstaller
.\tools\build_exe.ps1
```

패키지 자체 검사:

```powershell
.\release\EveryLock.exe --self-test
```

상단의 `취약 모드`와 `방어 모드`를 전환한 뒤 같은 입력으로 결과를 비교한다. `분석 콘솔`에서 SQL 인젝션, XSS, 세션 노출 및 상세 오류 노출 결과를 확인할 수 있다. 우측 `학부모 간편조회`는 IDOR 비교 화면을 연다.

`계정 잠금 실험`은 10~1,000개의 `SIM` 표기 가상 계정에 내부 실패 이벤트를 분배한다. 실제 HTTP 로그인 자동화가 아니라 같은 Node 프로세스의 메모리 상태만 변경한다. `관리자` 링크는 `/admin`을 열어 잠긴 가상 계정을 개별 또는 일괄 해제한다.

`http://127.0.0.1:4173/tool`의 **EveryLock Local Attack Console**은 숫자형 가상 학번, 이벤트 진행률, 계정 상태 맵, 실시간 공격 스트림과 잠긴 학번 목록을 한 화면에 표시한다. 계정이 10회 실패에 도달하면 터미널에 `2026xxxxxx Lock Success!` 형식으로 기록된다. 대상 주소는 UI와 서버 모두 loopback으로 고정되어 있다.

일반 로그인 폼에서도 잘못된 비밀번호를 입력하면 사진에서 관찰된 흐름을 재현한다.

- 1~4회: 현재 실패 횟수 안내
- 5~9회: 비밀번호 재설정 및 10회 잠금 사전 안내
- 10회: 계정 잠금 및 관리자 문의 안내

문구와 임계값은 관찰 화면을 연구 목적으로 재현한 것이며 실서비스 동작을 보증하지 않는다.

별도 터미널에서 API 시뮬레이션을 확인할 수 있다.

```powershell
node test.mjs
```

## 시나리오

### SQL 인젝션

1. `실습 페이로드 채우기`를 눌러 아이디에 `' OR '1'='1`을 넣는다.
2. 취약 로그인은 입력값을 SQL 문자열에 합친 것으로 가정하여 가짜 계정 인증을 우회하고 HTTP 200을 반환한다.
3. 안전 로그인은 입력값을 데이터로만 비교하므로 HTTP 401로 거부한다.

실제 데이터베이스를 사용하지 않으며, 화면에는 취약 구현이 만들었을 법한 가짜 쿼리만 표시한다.

### XSS

1. `무해한 실습 예시 채우기`를 누른다.
2. `취약 방식 실행`을 누르면 `.html()` 또는 `innerHTML`이 입력을 HTML로 해석하여 상태 문구가 바뀐다.
3. `안전 방식 실행`을 누르면 입력이 글자로만 표시된다.

이 예시는 페이지 문구만 변경하며 쿠키 읽기, 네트워크 전송, 파일 접근을 하지 않는다.

### 세션 식별자 노출

1. `인라인 노출 확인`을 누른다.
2. HttpOnly 쿠키는 `document.cookie`에서 보이지 않지만 같은 값이 `window.exposedSession`에서 보이는 것을 확인한다.
3. 안전 구현은 세션 대신 용도와 수명이 제한된 별도 nonce를 반환한다.

### IDOR

1. 관계없는 학생 `20260002`를 선택한다.
2. 취약 서버는 학생 정보를 반환한다.
3. 안전 서버는 학부모와 학생의 관계를 확인하고 HTTP 403으로 거부한다.

### 오류 정보 노출

1. 취약 오류 처리는 가짜 내부 클래스명과 파일 위치를 반환한다.
2. 안전 오류 처리는 일반 메시지와 추적번호만 반환한다.

## jQuery 관련 참고

페이지는 관찰한 버전과 동일한 jQuery 1.12.1을 공식 CDN에서 불러온다. CDN 접속이 불가능하면 XSS 실습은 내장된 `innerHTML` 대체 코드로 동작한다. 이 실습은 CVE-2020-11022/11023의 모든 세부 조건을 재현하기보다, 신뢰하지 않는 데이터를 HTML DOM 조작 함수로 전달하는 위험한 데이터 흐름을 보여준다.
