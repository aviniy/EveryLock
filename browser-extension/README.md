# EveryLock Browser Extension

계정 잠금 기능이 오히려 서비스 가용성에 문제를 일으킬 수 있지 않을까 싶어서 만들어본 크롬 확장 프로그램임.

쉽게 말하면 가상의 계정에 로그인 실패를 반복적으로 발생시켜서 계정이 잠기는 과정을 확인하는 프로그램임.

실제 사이트를 공격하는 건 아니고, 로컬 서버에서 계정 잠금 정책이 어떻게 작동하는지 실험하는 용도임.

## 1. 주요 기능

- 여러 가상 계정 ID 입력 가능
- 계정마다 로그인 실패 횟수 설정
- 요청 간격 조절 가능
- 실행, 일시정지, 재개, 중단 기능
- 특정 패턴으로 가상 계정 ID 자동 생성
- 잠긴 계정 목록 확인
- 실험 결과 JSON 파일로 저장
- 로컬 EveryLock 서버와 연동

## 2. 설치 방법

1. 크롬 주소창에 `chrome://extensions` 입력
2. 우측 상단 개발자 모드 활성화
3. 압축해제된 확장 프로그램 로드 클릭
4. `manifest.json`이 있는 폴더 선택
5. EveryLock 로컬 서버 실행
6. 확장 프로그램 실행

## 3. 사용 방법

먼저 EveryLock 로컬 서버를 실행하고 `http://127.0.0.1:4173`에 접속하면 됨.

이후 확장 프로그램에서 가상 계정 ID를 입력하거나 자동으로 생성하면 됨.

계정당 로그인 실패 횟수와 요청 간격을 설정하고 START를 누르면 시뮬레이션이 시작됨.

실행 결과는 로컬 대시보드에서 확인할 수 있고, 어떤 계정이 잠겼는지도 볼 수 있음.

## 4. 가상 계정 생성

계정 ID를 하나씩 입력하기 귀찮아서 자동 생성 기능도 넣음.

기본 형식은 다음과 같음.

- `2026------`
- `2025------`
- `2024------`
- `2023------`

`-` 부분에는 무작위 숫자가 들어감.

실제 학번이 아니라 실험용으로 생성한 가상 ID임.

## 5. 버튼 설명

| 버튼 | 기능 |
|---|---|
| START | 시뮬레이션 시작 |
| PAUSE | 일시정지 |
| RESUME | 다시 실행 |
| STOP | 실행 중단 |
| EXPORT JSON | 결과를 JSON 파일로 저장 |
| CLEAR | 기존 실험 기록 삭제 |

## 6. 실험 설정

처음부터 많은 계정으로 실험하기보다는 적은 수로 테스트하는 게 좋을 것 같음.

일단 다음 설정을 권장함.

- 가상 계정 5개 이하
- 계정당 로그인 실패 3회
- 요청 간격 500ms 이상
- 로컬 서버에서만 실행

## 7. 관련 취약점

이번 프로젝트와 관련된 CWE는 다음과 같음.

### CWE-645: Overly Restrictive Account Lockout Mechanism

계정 잠금 정책이 지나치게 엄격하면 공격자가 의도적으로 로그인 실패를 발생시켜 정상 사용자의 계정까지 잠기게 만들 수 있음.

즉, 계정을 보호하려고 만든 기능이 오히려 정상 사용자의 서비스 이용을 방해할 수도 있다는 거임.

### CWE-204: Observable Response Discrepancy

서버가 상황에 따라 서로 다른 응답을 반환하면 공격자가 그 차이를 통해 내부 정보를 추측할 가능성이 있음.

### CWE-203: Observable Discrepancy

서버의 응답이나 동작에서 관찰할 수 있는 차이가 발생하고, 이러한 차이가 정보 노출로 이어질 수 있는 문제임.

## 8. 실험 목적

이번 프로젝트에서 확인하고 싶은 건 단순히 계정을 잠그는 게 아님.

**계정을 보호하기 위한 보안 정책이 오히려 서비스 가용성을 떨어뜨릴 수 있다는 점을 확인하는 게 목적임.**

예를 들어 로그인에 5번 실패하면 계정이 잠기는 시스템이 있다고 가정해 보자.

공격자가 여러 계정에 의도적으로 로그인 실패를 발생시키면 정상 사용자가 자신의 계정에 로그인하지 못하는 상황이 생길 수도 있음.

이러한 문제를 로컬 환경에서 재현해 보고, 기존 계정 잠금 정책과 개선된 인증 정책을 비교해 보려고 함.

## 9. 제한 사항

이 프로그램은 로컬 실습용으로만 만들었음.

실제 대학 포털이나 외부 로그인 서비스에는 사용할 수 없도록 설계함.

실제 계정 수집이나 계정 존재 여부 확인, 로그인 자동화, 보안 통제 우회 등의 기능은 지원하지 않음.

또한 실제 비밀번호나 쿠키, 세션 정보 등을 수집하거나 저장하지 않음.

## 10. 한계점

이번 실험은 어디까지나 가상 환경에서 진행하는 시뮬레이션임.

따라서 실험에서 계정 잠금 문제가 발생했다고 해서 실제 대학 포털이나 다른 서비스에도 동일한 취약점이 존재한다고 단정할 수는 없음.

실제 서비스는 추가적인 보안 정책이나 요청 제한 기능이 적용되어 있을 수 있기 때문임.

## 11. 마무리

보통 계정 잠금 기능은 무차별 대입 공격을 막기 위한 보안 기능이라고 생각했음.

그런데 반대로 생각해 보면 공격자가 이 기능을 악용해서 정상 사용자의 계정을 잠그는 것도 가능하지 않을까 싶었음.

그래서 직접 로컬 환경을 만들어서 실험해 보기로 함.

이번 프로젝트를 통해 **보안성을 높이기 위한 정책이 오히려 가용성에 악영향을 줄 수도 있다는 점**을 확인하고, 이를 개선할 방법도 고민해 보려고 함.
